# 3つ目：「アイコンの自動整列」の検知（版 0.3.2）

仕様書 4 章の「自動整列がオンなら止まり、ログで警告する」です。コンパイルは x64 と x86 の両方で通っていますが、実機ではまだ動かしていません。

## 変わったこと

- 前から、mod が動き出すときに自動整列がオンなら、何もしないようにしていました。0.3.2 では、mod が動いている最中の切り替えにも対応しました。
  - オンにすると、mod は止まります。アイコンはすべてホームに集まり、ホイールでは動かなくなります。
  - オフに戻すと、mod はまた動き出します。アイコンはホームに集まったままです。
- 自動整列がオンのあいだも、作業領域は広げたままにします（0.3.4 から。理由は下の「0.3.2 の結果」の V）。
  - そのため、アイコンが1画面に収まらないほど多い（この画面では 180 個ほど）と、Explorer が見えない右のページへ並べるおそれがあります。0.3.2 では1画面に戻していましたが、それでも収まらない分は重なるだけです。
- 無効化や自動整列でアイコンをホームに集めたあとは、次に動き出すときもホームから始めます（v0.2 の既知の問題「集めたあとも前の位置から始まる」の修正）。

## 分かったこと（2026-10-30、Claude が外から確かめました）

- 右クリックメニューの「アイコンの自動整列」は、`IFolderView2` のフラグ `FWF_AUTOARRANGE` と、ListView のスタイル `LVS_AUTOARRANGE` の両方に反映されます。mod はスタイルの変化（`WM_STYLECHANGED`）で気づきます。
- `tools/desktool.cpp` に `flags`（今の状態を見る）と `arrange 0|1`（切り替える）を足しました。
- 0.3.1 のまま自動整列をオンにしたところ、右のページにあった1個を含め、53 個すべてがホームに並びました。オフに戻しても、アイコンはホームのままでした。

## 0.3.2 の結果（2026-10-30）

- U：OK。
- V：ホイールでまた動きます。ただ、オフに戻すと、アイコンが自動整列をオンにする前の並びに戻りました（ユーザーのスクリーンショットで確認）。
  - 原因：Explorer は、作業領域の大きさごとに、アイコンの並びを別々に覚えています。0.3.2 は、オンにしたときに作業領域を1画面に戻し、オフにしたときにまた広げていました。広げた時点で、Explorer が「広い作業領域のときの並び」、つまりオンにする前の並びを出していました。外から同じ切り替えをすると、53 個すべてがオンにする前の位置に戻りました。
  - 作業領域を広げたまま切り替えると、整列した並びがそのまま残りました。そのあとで mod が動き出しても、並びは変わりませんでした。
  - 整列中に (0,5) だったアイコンが、オフに戻すと (24,2) になります。これはどのアイコンも同じ量で、mod を止めていても同じでした。Explorer 自身の動きです。
  - 修正（0.3.4）：自動整列のあいだも、作業領域を1画面に戻さないようにしました。
- W：何度試しても、再起動のあとは自動整列がオフに戻っていました。X は飛ばしました。
  - 原因：Explorer は、自動整列の切り替えを、F5 を押したときか Explorer を閉じたときにしかレジストリ（`FFlags`）に書きません。タスクマネージャーからの再起動では、書かないまま終わることがあります。オンのまま F5 で保存してから再起動すると、mod は正しく止まりました（ログに `WARNING: "Auto arrange icons" is on`）。
  - 修正（0.3.3）：自動整列の切り替えに気づいたら、`IShellView::SaveViewState` でその場で保存させます。外から呼ぶと、すぐに `FFlags` が書き換わることを確かめました。
- Y：OK。

ユーザーから、ほかに2つの報告がありました。

- アイコンを置いてから、置いた位置に表示されるまでが遅く感じる。前からかどうかは分からず、許容範囲。
  - まだ調べていません。v0.2 で分かった描画の重さ（ListView を 2 画面分の幅にしているため）と関係があるかもしれません。
- まれに、置いた場所と違う場所へアイコンが飛ぶ。
  - ログに手がかりがありました。ホームの中へのドロップなのに、mod のドロップ後の置き直し（`FixClampedDrop`）が、アイコンを動かしていました（`Drop: moved 1 of 1 icon(s) past the clamp (dx=-318 dy=247)`）。
  - 原因：置き直しは、ドラッグを始めた位置として、`DoDragDrop` が呼ばれた瞬間のカーソル位置を使っていました。Explorer は、カーソルがある程度動いてからドラッグを始めます。素早く動かすと、その時点でカーソルはもう動いています。そのため、移動量を実際より少なく見積もり、Explorer が押し戻したと勘違いしていました。
  - 修正（0.3.5）：
    - ドラッグを始めた位置として、ボタンを押した位置（`WM_LBUTTONDOWN`／`WM_RBUTTONDOWN`）を使うようにしました。
    - ホームの中へのドロップは、Explorer が押し戻さないので、置き直しをしないようにしました。

## 置いてから表示されるまでが遅い（0.3.6 で修正）

- ユーザーが版を入れ替えて比べました。0.2 は速く、0.3.0 から遅くなっていました。ドラッグの処理を外した版（`DoDragDrop` をフックしない版）では速くなりました。
- ドロップにかかる時間をログに出す版で測ると、次のとおりでした。
  - ドロップのあと、mod の中で毎回 167〜188 ms かかっていました。
  - Explorer が置き直したアイコンを描き始めるのは、ドラッグが終わってから 189〜218 ms 後でした。
- 原因：ドラッグが終わると、mod は自動スクロールの補助スレッドの終了を待ちます。そのスレッドは、15 ms ごとに `SendMessageTimeout` でデスクトップのスレッドへ `kDragTick` を送っています。ちょうど送っている最中だと、2つのスレッドがお互いを待つ形になります。そのまま、タイムアウトの 200 ms が切れるまで止まっていました。
- 修正（0.3.6）：補助スレッドの終了を待つあいだも、送られてきたメッセージを処理するようにしました（`MsgWaitForMultipleObjects` と `QS_SENDMESSAGE`）。

|---|---|
| AA | 置いてから表示されるまでが、0.2 と同じくらい速くなったか |
| AB | 端での自動スクロール（J〜M）が今までどおり動くか |

# 2つ目：新しいアイコンを今見ている画面に出す（版 0.3.1）

仕様書 3.4 の「新しく増えたアイコンは、今見ている画面の空き位置に出す」です。コンパイルは x64 と x86 の両方で通っていますが、実機ではまだ動かしていません。

## 変わったこと

- ダウンロードや貼り付けで、デスクトップにファイルが増えたときの動きです。今見ている画面の外に出たアイコンを、今見ている画面の空き位置へ移します。空き位置は、Explorer と同じく、左の列から上から順に探します。
- 今見ている画面に置かれたアイコンはそのままです。ドロップしたものや、右クリックの「新規作成」で作ったものなどです。
- 設定「Put new icons on the screen you are looking at」（既定オン）で切り替えられます。

## 仕組みと、分かったこと

- 0.5 秒ごとに、デスクトップのアイコンの数を確かめます。増えていたら、名前を前の一覧と比べて新しいアイコンを見つけます。
- 初めは、Windows の変更通知（`SHChangeNotifyRegister`）を使うつもりでした。しかし、ふつうにファイルを書いただけでは通知が届きませんでした。ファイルを作ったアプリが `SHChangeNotify` を呼んだときだけ届きます。そのため、数を確かめる方法にしました。確かめたツールは `tools/newitemtest.cpp` です。
- Explorer 自身は、ふつうに書いたファイルも2秒以内にデスクトップに出します。出る場所は、ホームの最初の空き位置（今回は (327,2)）です。
- F5 のときは、アイコンがいったん消えてから戻ります。戻ったアイコンを「新しい」と間違えないように、次のときは動かしません。
  - 数が減った直後と、一度に4つ以上増えたときから、2秒間
  - 有効にした直後

# 1つ目：ドラッグ中の自動スクロール

## 第2版：少しずつ動く（2026-10-30）

第1版（ページ単位で動く）は、下の A〜I がすべて想定どおりでした。ただ、ユーザーの希望で、少しずつ動く形に変えました。コンパイルは x64 と x86 の両方で通っていますが、実機ではまだ動かしていません。

- 端で 0.5 秒待ったあとは、カーソルを端から離すまで、その方向へ動き続けます。ホームと右端では止まります。
- 速さは、最初は設定の 40%（既定で秒速 600 px）です。1秒かけて設定の速さ（既定で秒速 1500 px）まで上がります。
- 設定「Top speed while dragging at the edge, in pixels per second」（既定 1500）を足しました。
- 修正：デスクトップが WorkerW の下にあるときに、作業領域を広げ直す指示が届いていなかったのを直しました（6c38d84）。

## 第1版：ページ単位で動く

- アイコンをドラッグしたまま、カーソルを画面の左端か右端で止めると、0.5 秒後にその方向の次のページへ移ります。そのままドロップすれば、そのページに置けます。
  - 端で止め続けると、さらに次のページへ進みます（ページを2つ以上にしているとき）。
  - ホイールで半端な位置にいたときは、ページの区切りまで動きます。
- 設定が2つ増えました。
  - 「Move to the next page while dragging icons at the screen edge」：オン／オフ
  - 「Wait at the edge before moving, in milliseconds」：端で待つ時間（既定 500）
- ドラッグ中にページが動いたときも、ドロップのあとの置き直し（`FixClampedDrop`）が、動いた分を足して位置を計算します。

**仕組み**：ドラッグ中は Windows のドラッグ処理がマウスを握っていて、デスクトップにはマウスのメッセージが届きません。そこで、ドラッグのあいだだけ別のスレッドを動かし、15 ms ごとにデスクトップへ「今カーソルはどこか」を確かめさせています。

**できないこと**：Explorer の外のアプリ（ブラウザーなど）から始めたドラッグでは、自動スクロールしません。デスクトップとエクスプローラーのウィンドウから始めたドラッグだけが対象です。
