# v0.1 技術検証の手順

v0.1 では、スクロールの方法として3つの候補を比べます（仕様書 6.2）。モッドの設定「Scrolling method」で切り替えます。

| 設定値 | 方式 | しくみ |
|---|---|---|
| `window`（既定） | 1. ウィンドウを広げてずらす | アイコン層の `SysListView32` を「1画面 ×（1 + 追加ページ数）」の幅に広げ、左へずらして表示します。アイコンの座標は変えません。 |
| `origin` | 2. ListView のスクロール | `LVS_NOSCROLL` を外し、`LVM_SCROLL` でビューの原点を動かします。 |
| `items` | 3. 座標の書き換え | すべてのアイコンに、毎フレーム `LVM_SETITEMPOSITION` を送ります。**保存される配置が壊れるおそれがいちばん大きい方式です。** |

## 0. テストの前に：アイコン配置のバックアップ

テストを始める前に、毎回アイコン配置を書き出してください。PowerShell かコマンドプロンプトで、次を実行します。

```bat
reg export "HKCU\Software\Microsoft\Windows\Shell\Bags\1\Desktop" "%USERPROFILE%\Documents\desktop-icons-backup-v01.reg" /y
```

あわせて、デスクトップのスクリーンショットも撮っておくと、元の配置と比べやすくなります。

**配置を元に戻すとき**：Explorer は終了するときに今の配置を保存します。そのため、Explorer を止めてから読み込みます。

```bat
taskkill /f /im explorer.exe
reg import "%USERPROFILE%\Documents\desktop-icons-backup-v01.reg"
start explorer.exe
```

**Explorer が落ち続けたとき**：Windhawk が警告を出したら、モッドを止めてください。Windhawk の画面が開けないときは、タスクマネージャーで `windhawk.exe` を終了してから Explorer を再起動します。止めたあとで、イベントビューアーの「Windows ログ → Application」に出る、イベント ID 1000 の内容（落ちたモジュールとオフセット）を Claude に伝えてください。Claude が自分で読み取ることもできます。

## 1. モッドの組み込み

1. Windhawk を開き、「Create a New Mod」を押します。
2. エディタの中身をすべて消して、`sidetop.wh.cpp` の内容を貼り付けます。
3. エディタの左側にある「Enable logging」にチェックを入れます。ログは、チェックを入れたあとに起きたことしか残りません。
4. 左の「Compile Mod」（Ctrl+B）を押します。
5. ログを見るときは、エディタの「Show log output」を開きます。

アイコン層を見つけると、ログに `Found existing desktop ListView` と `Active: method=window ...` が出ます。

## 2. 方式ごとに確かめること

方式を切り替えると、ほかのページにあるアイコンはいったんホームへ集められます。そのあと、新しい方式で動き始めます。各方式で、次の表を確かめてください。

| # | 確かめること | 見るところ |
|---|---|---|
| a | ホイール下で右へ、ホイール上で左へ動くか | 画面 |
| b | ホームより左へ行かないか | 画面 |
| c | 動いているあいだに、ちらつき、遅れ、カクつきがないか | 画面、ログの `Settled at ... avg ... us, max ... us` |
| d | 壁紙が動かずに止まっているか。アイコンの背景に壁紙のずれや黒い部分が出ないか | 画面 |
| e | アイコンを右のページへドラッグできるか。そこでクリック、右クリックメニュー、ラッソ選択ができるか | 画面 |
| f | 右のページに置いたアイコンが、勝手にホームへ戻されないか | 画面、ログの `Overrode a move/resize` |
| g | Ctrl+ホイールでアイコンの大きさが変わるか（純正の動作） | 画面 |
| h | 右のページを表示したまま、F5 で再描画したり新しいファイルを作ったりしても崩れないか | 画面 |
| i | 下の「レジストリの確認」で、配置が壊れていないか | レジストリ |
| j | モッドを無効にすると、右のページのアイコンがすべてホームへ戻るか | 画面、ログの `Gather: moved N icon(s)` |

**レジストリの確認（i）**：右のページにアイコンを1つ置き、ホームへ戻ります。そのあと次のどちらかを試して、アイコンがどこに出るかを見ます。

- モッドを入れたまま Explorer を再起動します（タスクマネージャーで「エクスプローラー」を右クリックし、「再起動」を選びます）。
- モッドを無効にしてから、Explorer を再起動します。

## 3. 報告していただきたいこと

各方式について、表の a〜j の結果（○ / × / 気づいたこと）を書いてください。ログの `ListView ... style=...` で始まる3行と、`Settled at ...` の行もあわせて貼ってください。

## 前もって分かっている制限（v0.1）

- 右端は「ホーム + 追加ページ数」で止まります（既定は1ページで、合わせて2画面分）。
- Windhawk は、すでに保存されている設定を新しい既定値で上書きしません。前の版で試したときは、設定の「Pages added to the right of home」を手で 1 にしてください。
- マルチモニターでは、全モニターをまとめて1ページとして扱います。
- 「アイコンの自動整列」がオンのときは何もせず、ログに警告を出します。
- **【未解決】モッドを入れた直後は、右のページの配置が F5 で戻ります**（2026-10-29 確認、コミット 7693432）。スクロールやドロップはすぐに動くように見えますが、F5 を押すとアイコンが元の画面に戻されます。Explorer を一度再起動すると、F5 でも再起動でも右のページに残る、理想の挙動になります。
  - 原因の見込み：Explorer が起動するときは、作業領域を広げる処理（`CDesktopBrowser::SetDesktopWorkAreas` のフック）が最初から効きます。動いている Explorer にモッドを入れたときは、`WM_SETTINGCHANGE`（`SPI_SETWORKAREA`）を送って作業領域を計算し直させています。この通知が配置エンジンまで届いていない可能性があります。
  - 当面の回避策：モッドを入れたら（または設定を変えたら）、Explorer を一度再起動してください。
- ホイールは、カーソルの下にあるウィンドウに届きます（Windows の設定「ポイントしたときに非アクティブウィンドウをスクロールする」がオンの場合）。この設定がオフだと、デスクトップをクリックしてからでないと効かないことがあります。
