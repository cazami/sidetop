## 3. 仕様書 6.2 への答え

**アニメーション中のちらつきや遅延**
- ListView をずらしたとき、壁紙の部分が古い画面のまま残る「にじみ」が出ました。`SetWindowPos` に `SWP_NOCOPYBITS` を付け、すぐに `UpdateWindow` することで直りました。
- 今のアニメーションは 10 ms のタイマーで動かしています。実際には1コマに 26〜38 ms かかっていて、少しカクつきます。v0.2 で、画面の更新（垂直同期）に合わせた、時間で進むアニメーションに変えます。

**画面外のアイコンを Explorer が勝手に画面内へ戻すか**
- 戻します。いちばん手こずった点です。仕組みは次のとおりです。
  - デスクトップの ListView は owner-data（`LVS_OWNERDATA`）です。アイコンの位置を覚えているのは ListView ではなく DefView（`SHELLDLL_DefView`）です。そのため、`LVM_SETITEMPOSITION` で動かしても、F5 で元に戻ります。
  - DefView の中には、配置エンジン（`IconLayoutEngine`）があります。作業領域を元に格子を作り、F5 や読み込みのたびに、作業領域の外にあるアイコンを画面内へ戻します（`WorkspaceData::ResolveOffScreenIcons`）。
  - この作業領域は、`CDesktopBrowser::SetDesktopWorkAreas` から渡されます。ListView のメッセージを通らないので、サブクラス化では見えません。
- 対策は次の2つです。
  - Windhawk のシンボルフックで `SetDesktopWorkAreas` を書き換え、いちばん右の作業領域をページの分だけ広げて渡します。
  - アイコンの位置は `IFolderView::SelectAndPositionItems` で設定します。`IFolderView` は ShellWindows（`SWC_DESKTOP`）から取ります。Progman は `WM_GETISHELLBROWSER` に答えないためです。

**クリック、右クリックメニュー、ドラッグ&ドロップ、ラッソ選択**
- どれも純正のまま動きます。
- ただし、デスクトップ内でドロップしたアイコンだけは、今も1画面の中に押し戻されます。この押し戻しは、配置エンジンの作業領域とは別の場所で起きています（作業領域を広げても直りませんでした）。そこで、`DoDragDrop` をフックし、ドロップのあとで、押し戻されたアイコンを落とした位置へ置き直しています。この処理を外すと右のページに置けなくなることを、2026-10-29 に確かめました。
- ListView の作業領域を ListView に直接設定するとき、モニターの数より多く設定すると、comctl32 の中で Explorer が落ちました（`COMCTL32.dll+0x8ee43`）。いちばん右の作業領域を広げるだけなら落ちません。

**配置の保存先に、ずれた座標が書き込まれて壊れないか**
- window 方式はアイコンの座標を変えず、ListView ごとずらすだけです。そのため、保存される座標は「ホームから見た本当の位置」になり、ずれません。
- F5 でも Explorer の再起動でも、配置が保たれることを確認しました。レジストリの中身そのもの（i）はまだ見ていません。

**壁紙をスクロールさせる方法**
- 未調査です。v1.0 の前に調べます。
- 分かっていることを書いておきます。window 方式は ListView だけを動かすので、壁紙は止まったままです（d）。壁紙は ListView の後ろ（Progman 側）に描かれています。shell32 の中にも、壁紙を描く仕組み（`CDesktopWallpaper`、`CWallpaperRenderer`）があります。
- 右端を2画面分で固定にしたので、横長壁紙やパララックスでも、動かす量が決まっていて扱いやすくなります。

**origin 方式と items 方式を採用しない理由**
- アイコンが画面内へ戻されるのは配置エンジンが原因なので、どの方式でも `SetDesktopWorkAreas` の対策が必要です。そのため、origin 方式に変えても得はありません。
- items 方式は、毎フレームすべてのアイコンの座標を書き換えます。保存される配置を壊すおそれがいちばん大きく、アイコンが多いと重くなります。

## 4. 未解決の問題

1. **モッドを入れた直後は、右のページの配置が F5 で戻ります。** Explorer を一度再起動すると直ります。動いている Explorer に `WM_SETTINGCHANGE`（`SPI_SETWORKAREA`）を送っても、配置エンジンまで届いていない可能性があります。v0.2 で直します。
2. **ドロップのあとで置き直す処理に頼っています。** ドロップの瞬間には、アイコンがいったん1画面の端に見えるかもしれません。押し戻している場所を見つけられれば、もっと純正に近づけられます。
3. **Windows の版への依存**
   - `SetDesktopWorkAreas` の引数の形と、作業領域が最大16個並んだ配列で渡されることは、shell32 10.0.19041 を逆アセンブルして確かめたものです。
   - 関数は名前で探すので、Windows を更新しても見つかる見込みです。ただし、中身が変わると合わなくなるおそれがあります。
   - 見つからないときは、ログに出して、この対策なしで動きます。
   - 64 ビット版の Explorer にだけ対応しています。
4. **マルチモニター**：全モニターをまとめて1ページとして扱っています。モニターごとのスクロール（v1.0）は別に設計します。
5. **調べるためのログ**（`Position of item …`、`Drop: work area …` など）が残っています。v0.2 で整理します。
