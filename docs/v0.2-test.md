# v0.2 確認の手順

対象：コミット 152d805 以降の `sidetop.wh.cpp`（版 0.2.0）

2026-10-29 の夜に、ユーザーが寝ているあいだに Claude が書いた版です。コンパイルは x64 と x86 の両方で通っていますが、**実機ではまだ一度も動かしていません**。Windhawk に組み込むには管理者権限が要るため、Claude は自分で組み込めませんでした。

## 変わったこと

- **方式は window だけになりました**：スクロール方法の設定（window / origin / items）はなくなりました。
- **滑らかさと慣性**：アニメーションの進み方を、コマ数ではなく経過時間で決めるようにしました。1コマの描画が遅くても、動きにかかる時間は変わりません。
  - 設定「Glide (inertia), in milliseconds」（既定 100）で、ホイールを止めたあと滑るように動き続ける長さを変えられます。0 にするとすぐに止まります。
- **中ボタンでドラッグ**：マウスの中ボタンを押したまま左右に動かすと、デスクトップをつかんで動かせます。
- **ダブルクリックでホームへ**：アイコンのない場所をダブルクリックすると、ホームへ戻ります。設定「Double-click an empty spot to go back home」でオフにできます。アイコンの上でのダブルクリックは、今までどおりファイルを開きます。
- **位置の保存**：最後に見ていた位置を覚えておき、Explorer を再起動したあとにその位置から始めます。
- **作業領域の二重の広げすぎを直しました**：モッドを入れ直すと、ListView の作業領域が3画面分（5760）まで広がっていました。Explorer 側のフックが効いているときは、ListView の作業領域を直接広げる処理を動かさないようにしました。
- **ログの追加**：作業領域を計算し直させるときに `Asking Explorer ...` というログを出します。

## 1. 組み込みと、入れた直後の確認（Explorer を再起動せずに）

1. Windhawk のエディタに新しい `sidetop.wh.cpp` を貼り付けて、コンパイルします。
2. Explorer は再起動しないでください。
3. 右のページへアイコンを1つドロップし、F5 を押します。アイコンが右のページに残るかを見ます。
4. ログのうち、次の言葉を含む行を全部貼ってください。
   - `Asking Explorer`
   - `Desktop work areas`
   - `SetDesktopWorkAreas`
   - `Active:`
   - `Drop:`

**Claude の見込み**：「入れた直後だけ F5 で戻る」のは、初めて入れたときに Windhawk が shell32 のシンボルをダウンロードしていたためだと見ています。そのせいで、フックが付かなかったのかもしれません。

Claude が外から「無効化 → 有効化」を再現して試したときは、Explorer を再起動しなくても、再読み込みのあとに右のページに残りました。今回は残るはずです。もし戻ったら、`SetDesktopWorkAreas not found` という行が出ていないかを見てください。

## 結果（Claude が外から確かめた分、2026-10-30）

ユーザーが v0.2.0 を組み込んだあと（Explorer は再起動していない状態）、Claude が `desk.ps1` と `desktool.exe` で確かめました。

| 項目 | 結果 |
|---|---|
| 入れた直後にフックが効くか | 〇 `Desktop work areas (1): right edge 1920 -> 3840` が出ました。`not found` は出ていません |
| 右のページへ置いたアイコン（2448,2）が再読み込みのあとも残るか | 〇 残りました |
| 無効化（ホームへ集める）でアイコンが画面内へ戻るか | 〇 (529,311) へ戻り、ListView も 1920 幅に戻りました |
| 有効化し直して、作業領域が二重に広がらないか | 〇 3840 のままです（5760 になりません） |
| 位置の保存 | 〇 保存した 200 から始まりました |

気づいたこと：無効化するときは位置 0 を保存しないため、有効にし直すと、前に見ていた位置（200）から始まります。アイコンはホームへ集めたあとなので、少し不自然かもしれません。

**A のログ（`Settled at`）から分かったこと**
- 1コマにかかる時間は、表示している場所で大きく変わります。
  - ホーム付近（アイコンが多い）：30〜45 ms（22〜33 fps）
  - 右のページ（アイコンが少ない）：8〜15 ms（65〜120 fps）
- 遅いのはタイマーではなく、1コマごとの描き直し（アイコンと文字の描画）です。window 方式では ListView を動かすたびに、見えている範囲を全部描き直しています。
- もっと滑らかにするには、描き方を変える必要があります。たとえば、動いているあいだだけアイコンを描いた画像を使い回す方法です。これは大きな変更なので、後の版で調べます。
- 有効にしたあとの最初のスクロールだけ、1コマが 0.4〜3.5 秒かかることがありました。
